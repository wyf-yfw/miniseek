# MiniSeek-M0.1 MoE Design

Date: 2026-10-25  
Status: Approved for implementation planning  
Repo: `wyf-yfw/miniseek`  
Supersedes Stage-1 numeric defaults in `docs/STAGE_PLAN.md` for **M0.1 only** (1+8 / intermediate=1024 → 1+32 / intermediate=512; backbone still d=512, L=8).

## Goals

- First MoE line release: **MiniSeek-M0.1** (pretrained base later as `MiniSeek-M0.1-base`).
- Prefer **larger total params** with **many small experts**, not a few fat experts.
- Keep comparison fair vs Dense **D0.1** on locked mini pretrain; optionally strengthen later with full pretrain.
- **Out of scope for this stage:** tool/agent calling, SWA/CSA2/CED, chat SFT (SFT after MoE architecture freeze).

## Decisions (locked)

| Item | Choice |
|------|--------|
| Backbone | Scale with experts but stay in **100–200M** total-param band |
| Size preset | **d=512, n_layers=8, n_heads=8, head_dim=64, vocab=6400** |
| MoE layout | **Every layer** DeepSeekMoE-style FFN replacement |
| Experts | **1 shared + 32 routed**, **top-2** |
| Expert FFN | intermediate **512** (=d), GELU, two linear maps |
| Attention | **Full causal** (same as D0.1); SWA deferred to Stage 2 |
| Data (compare) | `pretrain_t2t_mini.jsonl` + fixed `valid.jsonl` |
| Data (strengthen) | Separate run on full `pretrain_t2t.jsonl` after architecture freeze |
| Aux loss | Load-balancing, default **λ=0.01** (configurable) |

## Architecture

```text
Token Embedding (V=6400 × d=512, tied with LM Head)
        ↓
×8 Transformer block:
  RMSNorm → Causal Self-Attn (RoPE) → residual
  RMSNorm → MoE(1 shared + 32 routed, top-2, h=512) → residual
        ↓
LM Head (tied)
```

### MoE block

- **Shared expert:** always applied to every token.
- **Routed experts:** router `Linear(d → 32)` → softmax → select top-2 → weighted sum of expert outputs.
- **Expert MLP:** `d → 512 → d` with GELU (no bias required; match Dense FFN style).
- **Auxiliary loss:** encourage uniform routed-expert usage (token-level); total loss = CE + λ · aux.

### Parameter budget (estimate, tie embeddings)

| Piece | Approx |
|-------|--------|
| Embedding (tied) | V·d ≈ 3.28M |
| Attn / layer | 4·d² ≈ 1.05M |
| MoE / layer | 33·(2·d·h) + router ≈ 17.30M + 0.016M |
| ×8 layers | ≈ 146.9M |
| **Total** | **≈ 150.2M** |

Activation per token ≪ total params: Attn + 1 shared + 2 routed experts.

**Acceptance:** `sum(p.numel() for p in model.parameters())` within **5%** of ~150M.

## Training & eval

### Compare track (required for Stage-1 gate)

- Data/tokenizer/valid locked same as D0.1.
- `max_seq_len=512`; BF16 on CUDA when available.
- Hyperparams: match D0.1 where possible; any change must be recorded in `eval/reports/stage-1.md`.
- Log: CE loss, aux loss, PPL, expert usage histogram.

### Strengthen track (optional, after freeze)

- Full `pretrain_t2t.jsonl`; does **not** enter architecture A/B leaderboard vs D0.1.

### Eval-Core

- Valid PPL, Gen-Smoke (seed=42), efficiency (peak VRAM, tokens/s).
- MoE probe: no single routed expert > **70%** of tokens (soft gate; investigate if violated).
- Relative gate vs D0.1: Valid PPL not worse by more than **~3%** (same spirit as `STAGE_PLAN.md`).

## Non-goals

- Tool / agent protocols and tool-call SFT.
- Changing tokenizer or vocab.
- Shipping chat weights in the first MoE drop (chat = later SFT repo without `-base`).

## Open implementation details (OK to decide in plan)

- Exact aux-loss formula (Switch-style vs DeepSeek-style) — pick one and unit-test.
- Whether shared expert shares the same MLP class as routed experts (yes, preferred).
- Dropless vs capacity-factor batching for top-2 — prefer simple dropless token→expert gather for this size.
