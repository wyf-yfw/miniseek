# 训练速度优化：基准与落地计划（2026-10-27）

## 目标

把「训练快不快」从感觉变成数字：对每一项优化做**单变量 A/B**，产出实测吞吐，而不是估算。

## 现状（已测量）

| 指标 | 值 |
|---|---|
| GPU | RTX 3090 24G，util 100%，显存只用 9.9 / 23.5 GB |
| 当前速度 | ~3.4 step/s |
| 有效 token | p50=426，mean=362，p80 触顶 512 |
| **padding 占比** | **29.3%**（随机组批）；按长度分桶后 0.7% |
| 截断率 | 58.5% 的样本被 512 截断 |
| 每步 GPU→CPU 同步 | 约 275 次（MoE 8 层 × (1 次 .cpu() + 32 次 .item())，外加 loss/ce/专家统计） |

## 候选优化

| # | 项 | 改动位置 | 语义影响 |
|---|---|---|---|
| 1 | 去掉 MoE 逐专家 `.item()`，每层一次 `offsets.tolist()` | `algo/model/moe.py` | 无（数学等价） |
| 2 | 负载统计不再每层 `.cpu()`，留 GPU 累加 | `algo/model/moe.py` | 无 |
| 3 | AdamW `fused=True` | `algo/train_pretrain.py` | 无（数值等价，误差量级内） |
| 4 | `torch.compile` | 训练脚本 | 无（可能重编译） |
| 5 | `log_every` 1 → 10（含专家统计降频） | 任务配置 | 只影响日志粒度 |
| 6 | 长度分桶组批 | `algo/train_pretrain.py` 采样器 | 改变批内长度分布 |
| 7 | 样本打包 packing（拼接后切块，无 padding 无截断） | 数据层 | 改变跨文档注意力边界 |

1、2 已落地（纯等价优化）；3–7 先测后定。

## 基准方法

`scripts/bench_train_opt.py`

- 固定从 `data/pretrain_mix_5g.jsonl` 蓄水池抽样 2048 条，**只做一次 tokenize**
- 固定权重（从 `best.pt` 载入），每个变体都从同一份权重起步
- warmup 10 步 + 测量 30 步，取**中位数**步时
- 指标统一为 **有效 token/s**（padding 不计入），另记 padding 占比与峰值显存
- 每个变体单独叠加在 `base` 之上（不是累积），用来隔离单项贡献；另跑一个 `all` 看合计
- `base` 通过把改动前的 `MoELayer.forward` 快照换回去来实现，保证对照的是真实旧行为

## 判定标准

- 单项 < 5% 视为噪声，不上
- 5%–15% 视实现复杂度决定
- > 15% 直接上
- 任何改变训练语义的项（6、7）即使更快，也要先确认 loss 曲线可比

## 执行顺序

1. 等当前训练（pid 56159，step ~54k/57k）跑完释放 GPU
2. 跑基准，拿到逐项数字
3. 把 1/2/3/5 这类等价优化直接合入
4. 6/7 给出实测后单独决策
